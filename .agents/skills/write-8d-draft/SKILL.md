# write-8d-draft

§7.4 **초안 템플릿 규칙**이다. 주 독자는 LangGraph `draft`·`cite_check`를 **구현·수정하는 코딩 에이전트**다. Streamlit/런타임이 사용자 질의로 초안을 쓰는 흐름(백로그 B3)과 혼동하지 않는다.

`CONTEXT.md`가 채워지면 도메인 용어는 거기를 가리킨다. `Draft`를 `interfaces/`로 고정할지는 사람 판단이며, 이 스킬에서 보호 경로를 건드리지 않는다.

보호 경로(`ontology/`, `interfaces/`, `eval/gold/`, `eval/baseline.json`, `.github/workflows/`)는 수정 제안만 한다.

## 사전 조건

- 검색 상위 5건과 근거 경로가 입력으로 있다 (없거나 허위면 검색부터 하거나 중단).
- 구현 대상이 Product의 draft/cite_check(또는 동등 모듈)인지 확인한다. “유사 사례로 초안만 써 줘”만 있고 코드 변경이 아니면 이 스킬의 주 경로가 아니다 — 템플릿을 참고용으로만 쓰고 Product 구현 Issue로 넘긴다.

## 절차

1. **입력 검증**
   - 상위 5건의 `odi_id`·`campaign_no`(해당 시)와 근거 경로가 실제 결과 집합에 있는지 확인한다.
   - **완료 조건**: 입력 ID가 모두 결과 집합에 있거나, 중단 사유를 남겼다.

2. **장애보고서 섹션**
   - 현상, 영향 범위(차종·부품), 추정 원인, 유사 사례 상위 5건(근거 경로 포함).
   - 추정은 “추정”으로 표시. `derived=true` 추출값은 추출임을 표시.
   - **완료 조건**: 네 항목이 모두 있고 사례에 원본 ID·근거 경로가 있다.

3. **조치계획 섹션**
   - 임시 조치, 근본 원인 조사 항목, 영구 조치 후보(유사 리콜 remedy), 효과 검증 방법.
   - **완료 조건**: 네 항목이 모두 있다.

4. **cite_check**
   - 초안의 모든 `odi_id`·`campaign_no`가 입력 결과 집합에 있는지 검사한다. 허위 ID가 있으면 재생성(또는 구현상 재생성 루프를 강제)한다.
   - **완료 조건**: 허위 ID 0개.

## 템플릿 (§7.4 약식)

```markdown
## 장애보고서
- 현상:
- 영향 범위 (차종·부품):
- 추정 원인: (추정)
- 유사 사례 (상위 5건, 근거 경로):
  1. odi_id=… / campaign_no=… — 경로: …

## 조치계획
- 임시 조치:
- 근본 원인 조사 항목:
- 영구 조치 후보 (유사 리콜 remedy):
- 효과 검증 방법:
```

도메인 용어: `CONTEXT.md` (비어 있으면 위 템플릿만으로 충분).

## 성공 조건

- [ ] 장애보고서·조치계획 섹션이 템플릿을 충족한다
- [ ] 허위 ID 0개 (cite_check 통과)
- [ ] 추정·`derived=true` 표시 규칙을 지켰다
- [ ] `interfaces/` 등 보호 경로를 무단 수정하지 않았다

## 하지 말 것

- 결과 집합에 없는 ID를 초안에 넣기
- 추정을 확정처럼 쓰기
- 추출값(`derived=true`)을 원본처럼 표시
- 이 Issue/스킬 단계에서 `src/factory_app/report/` 등 Product SSOT 경로를 새로 만들어 “완성”으로 간주하기 — SSOT 이전은 B3

## 후속 / 관련

- 런타임 구현: §11 백로그 B3 (초안 + cite_check), 파이프라인 §7.3
- 템플릿 SSOT를 코드로 옮길 때 이 스킬은 포인터만 남긴다
- `interfaces/`의 `Draft` 고정 여부: 사람 판단 (보호 경로 — 제안만)

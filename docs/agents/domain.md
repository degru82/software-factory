# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색할 때 이 리포의 도메인 문서를 어떻게 읽고 쓰는지 정한다.

## 탐색 전에 읽을 것

- 리포 루트의 **`CONTEXT.md`**: 이 리포의 용어집. 스킬이 `GLOSSARY.md`라고 하면 대신 `CONTEXT.md`를 읽고 쓴다.
- **`docs/adr/`**: 작업할 영역에 걸리는 ADR을 읽는다.

이 파일들이 없으면 **조용히 진행한다**. 없다고 지적하거나 미리 만들자고 제안하지 않는다. 용어나 결정이 실제로 정해질 때 `/domain-modeling` 스킬(`/grill-with-docs`, `/improve-codebase-architecture`에서도 호출됨)이 그때 만든다.

## 파일 구조

이 리포는 **단일 컨텍스트**다. `GLOSSARY-MAP.md`도, 컨텍스트별 용어집도 없다.

```
/
├── CONTEXT.md          ← 용어집 (GLOSSARY.md 역할)
├── docs/adr/
│   └── 0001-mcp-config-sync.md
└── src/
```

## 용어집의 어휘를 쓴다

출력물(Issue 제목, 리팩터링 제안, 가설, 테스트 이름)에서 도메인 개념을 부를 때는 `CONTEXT.md`에 정의된 용어를 쓴다. 용어집이 피하라고 한 동의어로 바꾸지 않는다.

필요한 개념이 용어집에 아직 없다면 신호다. 프로젝트가 쓰지 않는 말을 지어내고 있거나(다시 생각한다), 실제로 빈 곳이 있는 것이다(`/domain-modeling`용으로 기록해 둔다).

## 언어

용어 정의와 ADR은 한국어로 쓴다 (AGENTS.md 규칙 7). 영어 원어가 필요한 용어는 `한국어 용어 (English term)` 형식으로 병기한다.

## ADR과 충돌하면 드러낸다
